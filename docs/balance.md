# 밸런스 검증

기준을 숫자로 먼저 정하고, 원재료(시뮬레이션 분포·커버리지·효율)로 판정하고, 기준을 넘는 데 필요한 가장 작은 수치만 바꾼다.
판정은 사람이 아니라 `npm run check:balance`(헤드리스 시뮬레이션)와 실제 플레이 기록(`npm run replay`)이 한다.

## 1. 범위

캠페인 1장 NORMAL 1~10웨이브, 업그레이드 없는 기본 유닛 4종(SENTINEL, RAIL-X, ARC, CRYO). Phase 3에서 11~20웨이브와 업그레이드가 들어오면 같은 절차를 다시 돈다.

## 2. 판정 기준 (`tools/balance-check.ts`, 배치 시드 3개 × 40판)

| # | 기준 | 근거 |
| --- | --- | --- |
| 1 | 균형 빌드는 배치가 달라도 전부 클리어 | 10장: 균형 잡힌 빌드는 클리어 |
| 2 | 균형 빌드에서 한 유닛이 피해 50% 이상을 내고 이긴 판 0 | 19장: 그런 빌드가 이기면 밸런스 문제 |
| 3 | 무작위 빌드의 중앙값은 패배 | 19장: 무작위는 실패 |
| 4 | RAIL-X 몰빵의 코어 중앙값 50 이하 | 지배 전략 방지 (아래 B-01) |
| 5 | RAIL-X 몰빵이 균형보다 코어 중앙값 40 이상 낮다 | 같은 크레딧으로 조합이 확실히 낫다 |

**10웨이브에서 판정하지 않는 것:** "몰빵 빌드는 실패"(10장)는 1장 전체(20웨이브)에서 판정한다. SENTINEL·RAIL-X의 약점을 찌르는 적(은폐형 W11, 분열형 W13, 후반 중장갑·보호막 혼합)과 그 약점을 메우는 업그레이드(SENTINEL A2·C1)가 아직 없어서, 1~10웨이브만으로 몰빵을 실패시키면 균형 빌드도 같이 실패하거나 초반 3웨이브의 여유(1-1 "초보자는 첫 3웨이브 안에 규칙을 이해")가 사라진다. 아래 4절의 적 체력·시작 크레딧 탐색이 그 근거다.

빌드 정의 (`tools/depth.ts`): 몰빵 = 한 유닛만, 커버리지 상위 6칸 중 시드 무작위. 균형 = SENTINEL·SENTINEL·CRYO·ARC·RAIL-X·SENTINEL·ARC·RAIL-X 반복, 상위 6칸. 무작위 = 유닛과 칸(상위 60칸) 모두 시드 무작위. 모두 웨이브 사이에만 크레딧을 쓴다.

## 3. 원재료 (`npm run analyze`, 변경 전)

| 측정 | 결과 | 읽은 것 |
| --- | --- | --- |
| 커버리지: 경로에 닿는 칸 | SENTINEL 211/248 · RAIL-X **248/248** · ARC 207 · CRYO 161 | RAIL-X는 어디에 놓아도 경로 전체를 본다. 배치 판단이 없다 |
| 100CR당 실효 DPS (R-07) | SENTINEL 3.33 · RAIL-X **7.01** · ARC 5.79 · CRYO 0.33 | RAIL-X가 가장 싸고 가장 세다 |
| SENTINEL 몰빵 | 60/60 클리어, 코어 중앙 82 | 10웨이브 압력이 낮다 |
| 무작위 | 48/60 클리어, 코어 중앙 94 | 아무렇게 해도 이긴다 |
| SENTINEL 몰빵, 좋은 칸 vs 아무 칸 | 코어 중앙 82 vs 59 | 배치 판단 자체는 살아 있다 |

## 4. 탐색 (`npm run tune` 외, N=24~40)

| 레버 | 결과 |
| --- | --- |
| RAIL-X 사거리 7→6→5→4.5 | RAIL-X 몰빵 코어 중앙 96→84→82→60. 다른 빌드에는 거의 영향 없음 |
| 시작 크레딧 650→450 | 모든 빌드가 같이 약해짐. 몰빵 클리어는 유지 |
| 적 체력 ×1.3~1.45 | SENTINEL 몰빵이 지기 시작(×1.45에서 0/24)하지만 균형도 같이 실패(×1.4에서 17/24). RAIL-X 몰빵은 ×1.45에서도 24/24 |
| W6·W9 중장갑 ×2 | SENTINEL 몰빵 코어 82→46, 균형은 그대로(98). 대신 ARC 피해 비율이 50%를 넘음 |
| RAIL-X 사거리 5 + 피해 14 | RAIL-X 몰빵 중앙 33~46으로 떨어지고 균형은 40/40 유지 |
| ARC 연쇄 감쇠 0.85→0.75→0.70 | RAIL-X 약화 후 ARC가 균형 빌드 피해의 50%를 넘던 것을 해소. 0.75는 시드 2·3에서 50.4%·50.8%로 아슬아슬, 0.70은 최대 48.7% |

**결론:** 문제는 "웨이브가 쉽다"가 아니라 "RAIL-X의 사거리가 맵 크기를 넘는다"였다. 웨이브 압력을 올리는 레버는 모든 빌드를 같이 깎아서 판단 깊이를 만들지 못했다.

## 7. 사람 플레이 기록

- 결과 화면의 "플레이 기록 저장"이 JSON을 내려받는다: 입력 기록(틱), 각 입력의 실제 시각(ms), 일시정지 시간, 데이터 해시, 최종 상태 해시.
- `npm run replay -- 기록.json ...`이 현재 데이터로 다시 재생해 상태 해시가 같은지 확인하고, 웨이브별 코어 손상·수입, 설치·판매·우선순위 변경 수, 웨이브 사이 실제 생각 시간을 출력한다. 데이터 해시가 다르면 그 사실을 먼저 알린다.
- 자동 검수(`tests/touch.mjs`)가 이 경로 전체를 확인한다: 터치로 10웨이브 완주 → 기록 저장 → 헤드리스 재생 일치.
- 사람 플레이테스트 절차는 `docs/playtest.md` 2절.

## 8. 남은 것

- 1장 전체(20웨이브)에서 SENTINEL·RAIL-X 몰빵 실패 판정 (Phase 3, 은폐·분열·업그레이드 포함).
- 균형 빌드 봇은 순서가 고정된 단순한 플레이어다. 실제 사람이 더 잘하면 기준 1은 더 쉽게, 사람이 못하면 더 어렵게 나온다. 사람 기록이 쌓이면 봇의 배치 범위(상위 6칸)를 사람 분포에 맞춘다.
